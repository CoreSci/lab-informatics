# JCAMP-DX reader and validator

A dependency-light Python parser, validator and writer for **JCAMP-DX**, the open IUPAC plain-text exchange format for spectra (IR, UV-Vis, Raman and more).

**Problem it solves:** spectra move between instruments, databases and analysis tools as JCAMP-DX files, but the format has several compressed encodings and built-in integrity checks that simple readers ignore. A truncated or hand-edited file can load silently with wrong values. This tool decodes every standard 1-D encoding and **verifies the file's own checksums** (X-checks and Y-checks), so bad data is reported instead of passed on.

## Approach

Implemented from the published specification: McDonald & Wilks, *Applied Spectroscopy* 42(1), 1988, and the JCAMP-DX 4.24 conventions.

| Feature | Details |
|---|---|
| Data tables | `##XYDATA=(X++(Y..Y))` (evenly spaced), `##XYPOINTS=(XY..XY)`, `##PEAK TABLE=(XY..XY)` / `(XYW..XYW)` |
| Encodings | AFFN (free-format numbers) and the compressed ASDF forms **SQZ** (squeezed), **DIF** (difference) and **DUP** (repeat count), in any combination |
| Labels | Matched per the spec: case, spaces, `-`, `/` and `_` are ignored, so `##XY DATA` equals `##xydata`. `$$` comments are stripped. `##$…` private labels are kept. |
| Validation | Required labels, X-checks (each line's abscissa vs `FIRSTX`/`LASTX`/`NPOINTS`), DIF Y-checks (each line repeats the previous line's last ordinate), point count, `FIRSTY` vs decoded data, and a missing `##END` (truncation) |
| Writer | Produces AFFN or DIF/DUP-compressed `XYDATA` with Y-checks and lines of 80 characters or fewer. Used to generate the sample data. |
| Out of scope | Compound/linked files (`##BLOCKS`) and `##NTUPLES` (e.g. multi-dimensional NMR) are rejected with a clear error rather than half-parsed |

Findings come back as `Issue` objects with a level (`error` / `warning`) and a line number. Use `strict=True` (or `--strict`) to make any error fatal.

## Data

Everything in `sample-data/` is **synthetic**: seeded sums of Gaussian bands plus baseline and noise, generated by `generate_synthetic_spectra.py`. None of it is modelled on a real compound or instrument. Re-running the script reproduces the files byte for byte.

| File | Contents |
|---|---|
| `synthetic_ir_absorbance.jdx` | IR absorbance, 4000 → 400 cm⁻¹ (decreasing x), 1801 points, DIF/DUP compressed |
| `synthetic_uv_vis.jdx` | UV-Vis absorbance, 200 → 800 nm, 601 points, AFFN |
| `synthetic_ir_peak_table.jdx` | The IR band list as a `PEAK TABLE` |
| `invalid_example.jdx` | The IR file with planted defects: a corrupted Y-check, a shifted line abscissa, a wrong `NPOINTS` and a missing `##OWNER` |

## Run

```bash
pip install -r requirements.txt          # numpy; matplotlib only for --plot; pytest for tests

# summary + validation report (exit code 1 if any file has errors)
python jcamp_dx.py sample-data/*.jdx

# export and plot one spectrum
python jcamp_dx.py sample-data/synthetic_ir_absorbance.jdx --csv ir.csv --plot ir.png

# regenerate the synthetic sample files
python generate_synthetic_spectra.py

# unit tests
python -m pytest -q
```

From Python:

```python
import jcamp_dx

sp = jcamp_dx.read("sample-data/synthetic_uv_vis.jdx")
sp.x, sp.y                  # numpy arrays in real units (XFACTOR/YFACTOR applied)
sp.header("XUNITS")         # 'NANOMETERS'
sp.ok, sp.issues            # validation result
```

The validation report for `invalid_example.jdx` shows each planted defect once. A corrupted line produces a pair of Y-check errors, one where it starts and one where the next line starts, which pinpoints the line.

```
validation : 4 error(s), 1 warning(s)
  ERROR: line 20: Y-check failed: line starts with 29734, previous line ended with 19734
  ERROR: line 21: Y-check failed: line starts with 23451, previous line ended with 33451
  ERROR: line 22: X-check failed: line abscissa 3900, expected 3850 for point 76
  WARNING: missing ##OWNER (required since JCAMP-DX 4.24)
  ERROR: NPOINTS=1800 but the table holds 1801 ordinates (X-checks use the decoded count)
```

## Notes

- **Ambiguity rule:** a letter `E`/`e` after a digit is read as an exponent only when a sign follows (`1.5E+03`). Otherwise it's the SQZ pseudo-digit +5 / −5, as ASDF requires.
- Ordinates are stored as integers × `YFACTOR`. Round-tripping through the writer is exact to within `YFACTOR / 2`, and the tests check this.
- Requires Python ≥ 3.9 and NumPy.
